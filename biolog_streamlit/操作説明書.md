# BioLog 操作説明書（v1.5.5 時点）

家族の健康データを記録・閲覧するための画面操作手順をまとめます。

---

## 1. 起動方法

### 通常起動
```bash
cd <repository-root>
docker compose up -d
```

### 初回ビルド時 or コード変更後
```bash
docker compose up -d --build
```

### アクセス
ブラウザで http://localhost:8501 を開く。

### 停止
```bash
docker compose down
```

---

## 2. 画面構成

### サイドバー（左）
- **日付範囲（開始日／終了日）**：グラフ・一覧の表示期間を指定
- **ユーザー選択（複数可）**：表示対象のユーザー（self/father/mother）を選択
- **「更新」ボタン**：最新値が表示されない時に強制再取得
- **「ヘルスチェック」ボタン**：API が動作しているか確認

### メイン画面
- **サマリーカード**：3 ユーザー（自分・父・母）の最新値を縦カードで横並び表示
  - 体重 / 体温 / 脈拍 / 収縮期血圧 / 拡張期血圧
- **タブ 1：グラフ**：時系列グラフ
- **タブ 2：一覧**：レコード一覧 + CSV ダウンロード
- **タブ 3：新規登録**：データ登録フォーム
- **タブ 4：修正・削除**：既存レコードの編集・削除

---

## 3. データ登録手順（タブ 3）

1. 上部タブから **「新規登録」** を選択
2. **ユーザー** を選択（自分 / 父 / 母）
3. **日付** を選択（デフォルトは JST 今日）
4. 記録したい項目を入力：
   - 体温（°C）, 脈拍（bpm）, 収縮期血圧, 拡張期血圧, 体重, 体脂肪率, 筋肉量, 基礎代謝
   - メモ（短いテキスト）
   - 食事ログ（長文可）
   - 行動ログ（長文可）
5. **「登録」** ボタンを押す
6. 「登録を受け付けました（反映には数秒かかる場合があります）」と表示される
7. 一覧は約10秒ごとに自動更新される。すぐ確認したい場合は、サイドバーの
   **「更新」** を押す

### 注意事項
- 同一ユーザー × 同一日付の登録は **UPSERT（上書き）** されます
- 全ての数値項目を空のまま登録すると 422 エラー（最低 1 項目は必要）
- 範囲外の値（体温 30°C など）は Pydantic で弾かれる

---

## 4. データ修正手順（タブ 4）

1. 上部タブから **「修正・削除」** を選択
2. **修正セクション** で：
   - ユーザーを選択
   - 既存登録の **日付を selectbox** で選択
3. 既存値がフォームに自動プリフィルされる
4. 変更したい値を編集
5. **「更新」** ボタンを押す
6. 「更新完了 — 日付（ユーザー名）」と表示される

### 注意事項
- `request_id` / `id` は変更不可
- 数値を未入力（空）にすると更新対象外（保持される）
- 空文字 `""` の memo / meal_detail / activity_log は許可（クリア可能）

---

## 5. データ削除手順（タブ 4）

1. 上部タブから **「修正・削除」** を選択
2. **削除セクション** で：
   - **削除するレコード ID** を入力（一覧タブで `id` カラムを参照）
3. 対象レコードのプレビューがテーブルで表示される
4. 内容を確認したら **「上記レコードを削除することを確認します」** にチェック
5. **「削除実行」** ボタンを押す
6. 「削除完了 — ID: X」と表示され、フォームがクリアされる

### 注意事項
- 存在しない ID は「ID X のレコードは存在しません」警告のみ（削除ボタン非表示）
- 削除は即時実行・取り消し不可（バックアップしてから操作推奨）

---

## 6. CSV エクスポート（タブ 2）

1. 上部タブから **「一覧」** を選択
2. サイドバーで日付範囲・ユーザーを調整
3. テーブル下の **「CSV ダウンロード」** ボタンを押す
4. ファイル名 `biolog_<開始日>_<終了日>.csv` で保存される

### 仕様
- UTF-8 BOM 付き（Excel で日本語文字化けしない）
- 長文（メモ / 食事ログ / 行動ログ）は **省略せず全文** 出力
- 列順は一覧表示と同じ

---

## 7. 一覧画面の使い方（タブ 2）

### 通常表示
- 表示中データがHTMLテーブルで表示され、約10秒ごとに自動更新される
- 列ソートとセル選択は使用できない。必要に応じてCSVを利用する
- 長文列はテーブル上では省略表示：
  - メモ：40 文字超で `...`
  - 食事ログ：80 文字超で `...`
  - 行動ログ：200 文字超で `...`

### 全文表示（expander）
- 上記閾値を超えるセルがあると、テーブル下部に **「全文表示（省略された長文のみ）」** セクションが現れる
- expander のラベル：`対象日 / ユーザー / 列名`
- クリックで展開して全文を読める

### CSV は全文
- 画面上の省略は表示のみ。CSV ダウンロードは常に全文

## 8. グラフの見方（タブ 1）

### 描画対象
- 体重（kg）
- 体温（°C）
- 脈拍（bpm）
- 血圧（収縮期 / 拡張期）

### 配色
- self: 青 `#1f77b4`
- father: 緑 `#2ca02c`
- mother: 赤 `#d62728`

### 血圧グラフの参考線
- 収縮期 120 mmHg（水平線）
- 拡張期 80 mmHg（水平線）

### 集約ルール
- 1 日に複数登録があっても **1 日 1 点** に集約（最後の値）
- データが無い日はティック非表示

## 9. トラブルシューティング

### 表示が古い・更新されない
1. サイドバー **「更新」** を押す
2. 改善しない場合はブラウザを **完全リロード**（Ctrl + F5）
3. それでもダメなら `docker compose restart biolog-streamlit`

### 「API エラー」が出る
1. API コンテナの状態確認：
   ```bash
   docker ps -a
   docker logs biolog-api --tail 50
   ```
2. ヘルスチェック：
   ```bash
   curl http://localhost:8766/api/health/health
   ```
3. API が落ちている場合は再起動：
   ```bash
   docker compose restart biolog-api
   ```

### 起動失敗 / API が立ち上がらない
- `migration_lock` 残存の可能性：
  ```bash
  docker exec biolog-api python -c "
  import sqlite3
  conn = sqlite3.connect('/data/biolog.db')
  conn.execute('DELETE FROM migration_lock WHERE id = 1')
  conn.commit()
  conn.close()
  print('Lock released')
  "
  docker compose restart biolog-api
  ```

### SQLite ロックエラーが頻発
- `.db-shm` / `.db-wal` 残骸がないか確認：
  ```
  ${BIOLOG_DATA_DIR:-./data}/biolog.db-shm
  ${BIOLOG_DATA_DIR:-./data}/biolog.db-wal
  ```
  存在したら biolog-api を停止してから削除

### Streamlit が SyntaxError で起動しない
- `docker logs biolog-streamlit --tail 30` で原因確認
- 直近の編集で構文を壊した可能性

## 10. データのバックアップ

### 手順
1. 安全のため一度コンテナを停止：
   ```bash
   docker compose down
   ```
2. DB ファイルをコピー：
   ```
   コピー元: ${BIOLOG_DATA_DIR:-./data}/biolog.db
   コピー先: 任意の場所（例：./backup/biolog_2026-05-25.db）
   ```
3. 再起動：
   ```bash
   docker compose up -d
   ```

### 復元
1. `docker compose down`
2. バックアップした `.db` ファイルを `${BIOLOG_DATA_DIR:-./data}/biolog.db` に上書きコピー
3. `docker compose up -d`

### 定期バックアップ推奨
- Windows のタスクスケジューラで `docker compose down` → コピー → `docker compose up -d` を定期実行
