# BioLog 機能仕様書

> 対象: BioLog v1.7.5 相当（リポジトリ確認日: 2026-08-15）  
> この文書は、初めて BioLog を使う人にも「何ができるか」「どこに注意するか」が分かるように、画面の動きと内部の仕組みをまとめたものです。

## 1. BioLog とは

BioLog は、自分と家族の健康に関する数値や生活メモを、日付ごとに記録して振り返るための個人向けアプリです。

- ブラウザで操作します。
- 標準では同じ PC からだけ利用します。
- 記録は PC 内の SQLite データベースに保存します。
- 体重や血圧などの変化をグラフで確認できます。
- 一覧を CSV に書き出し、Excel などで保管・確認できます。

### このアプリの目的

毎日の健康記録を「入力する」「見る」「比べる」「書き出す」という作業を、1つの画面で行えるようにすることです。

### このアプリが対象とする人

- 自分の健康記録を日ごとに残したい人
- 自分・父・母の記録を1台の PC でまとめたい人
- クラウドではなく、自分の PC 内にデータを保存したい人

### このアプリが目的としないこと

- 病気の診断、治療、医学的な助言
- 医療機関・介護施設などの業務で使う健康情報管理
- 不特定多数が使うインターネットサービス
- 大人数のアカウント管理や権限管理
- AI による予測や健康判定

BioLog の表示だけで健康状態を判断しないでください。体調不良や異常値がある場合は、医師などの専門家に相談してください。

## 2. できること一覧

| 機能 | できること | 初心者向けの説明 |
|---|---|---|
| 最新値の確認 | 自分・父・母の最新の体重、体温、血圧、脈拍を表示 | アプリを開くと、直近の記録がすぐ見えます |
| 絞り込み | ユーザーと開始日・終了日を指定 | 見たい人と期間だけに絞れます |
| グラフ | 体重、体温、血圧、脈拍を時系列で表示 | 数値の変化を線で追えます |
| 複数人比較 | 選択した複数ユーザーを同じグラフに表示 | 自分・父・母の推移を見比べられます |
| 一覧 | 記録を新しい日付から20件ずつ表示 | 過去の記録を表で確認できます |
| 長文表示 | 省略されたメモ・食事・行動ログを展開 | 長い文章も必要なときだけ全文を読めます |
| 新規登録 | 日付、ユーザー、測定値、生活ログを登録 | その日の記録を追加できます |
| 修正 | 登録済みの日付を選び、内容を変更 | 入力ミスを後から直せます |
| 削除 | IDを指定し、内容を確認して削除 | 間違った記録を削除できます |
| CSV出力 | 選択したユーザー・期間の全件をCSV保存 | Excelなどで開けるバックアップ資料を作れます |
| 手動更新 | 画面のキャッシュを消して再取得 | 表示が古いときに最新状態へ更新できます |
| ヘルスチェック | API・データベース・書き込み処理の状態を確認 | アプリ内部が動いているか確認できます |

## 3. 記録できる内容

### 3.1 対象ユーザー

現在の標準構成では、次の3人に固定されています。

| 内部名 | 画面表示 |
|---|---|
| `self` | 自分 |
| `father` | 父 |
| `mother` | 母 |

自由な名前の追加やユーザーアカウント作成機能はありません。

### 3.2 測定値

| 項目 | 単位 | 入力できる範囲 |
|---|---:|---:|
| 体重 | kg | 0.1〜299.9 |
| 体温 | ℃ | 34.0〜42.0 |
| 収縮期血圧 | mmHg | 50〜250 |
| 拡張期血圧 | mmHg | 30〜150 |
| 脈拍 | bpm | 30〜200 |
| 体脂肪率 | % | 0.0〜100.0 |
| 基礎代謝 | kcal | 1〜4999 |
| 筋肉量 | kg | 0.1〜199.9 |

範囲外の値や、数字として解釈できない値は登録できません。

### 3.3 文章の記録

| 項目 | 用途例 | 最大文字数 |
|---|---|---:|
| メモ | 体調、服薬の事実、気づきなど | 10,000文字 |
| 食事ログ | 朝食・昼食・夕食・間食など | 10,000文字 |
| 行動ログ | 運動、外出、睡眠に関する行動など | 20,000文字 |

新規登録では、測定値を1つ以上入力するか、文章の記録を1つ以上入力する必要があります。すべて空の記録は登録できません。

## 4. 画面の構成

### 4.1 サイドバー

画面左側の共通操作エリアです。

- **ユーザー**: 自分・父・母から、表示したい人を複数選べます。初期値は「自分」です。
- **開始日 / 終了日**: グラフと一覧の対象期間を指定します。初期表示は、おおむね直近30日です。
- **更新**: 最新データを取り直して画面を再表示します。
- **ヘルスチェック**: APIやデータベースが動作しているか確認します。

### 4.2 最新データ

画面上部には、自分・父・母それぞれの最新記録が表示されます。

表示項目は、体重、体温、収縮期血圧、拡張期血圧、脈拍、最終更新日です。記録がない人には「データなし」と表示されます。

### 4.3 4つのタブ

1. **グラフ** — 測定値の変化を見る
2. **一覧** — 記録の内容を表で確認し、CSVを保存する
3. **新規登録** — 新しい日付の記録を入力する
4. **修正・削除** — 登録済みの記録を直す、または削除する

## 5. 機能ごとの仕様

### 5.1 グラフ

グラフには次の4種類があります。

- 体重
- 体温
- 血圧（収縮期・拡張期）
- 脈拍

動作ルール:

- サイドバーで選んだユーザーと期間だけを表示します。
- 同じ日付のデータは1日1点として扱います。
- ユーザーの色は、自分が青、父が緑、母が赤です。
- 血圧グラフには参考線として収縮期120、拡張期80が表示されます。
- 対象データがない場合は「データがありません」と表示します。

体脂肪率、筋肉量、基礎代謝は記録と一覧表示はできますが、現在の標準グラフには表示されません。

### 5.2 一覧

- 選択したユーザーと期間に一致する記録だけを表示します。
- 新しい日付が先になるよう並べます。
- 1ページに20件表示します。
- ページ番号を入力して移動します。
- 一覧部分は約10秒ごとに自動更新します。
- 表は安全なHTMLとして表示し、記録内のHTMLをそのまま実行しません。

長い文章は、表を読みやすくするため次の長さで省略します。

| 項目 | 表で省略する目安 |
|---|---:|
| メモ | 40文字を超える場合 |
| 食事ログ | 80文字を超える場合 |
| 行動ログ | 200文字を超える場合 |

省略された文章は、表の下にある「全文表示」から読めます。

### 5.3 CSVダウンロード

- サイドバーで選択したユーザーと期間の**全件**を出力します。
- 一覧で開いている20件だけではなく、条件に合う全ページ分が対象です。
- 長文は省略せず全文を出力します。
- ファイル名は `biolog_<開始日>_<終了日>.csv` です。
- UTF-8 BOM付きのため、Excelで日本語を開きやすい形式です。
- 文字列が `=`、`+`、`-`、`@` で始まる場合は、表計算ソフトで数式として実行されにくい形へ無害化します。

CSVには健康情報が含まれます。公開フォルダー、共有設定されたクラウド、GitHubなどへ誤って置かないでください。

### 5.4 新規登録

基本手順:

1. 「新規登録」タブを開きます。
2. ユーザーと日付を選びます。
3. 必要な測定値や文章を入力します。
4. 「登録」を押します。

登録後、画面への反映に数秒かかることがあります。すぐに確認したい場合は、サイドバーの「更新」を押します。

#### 同じ人・同じ日付をもう一度登録した場合

BioLogは、1人につき1日1件の記録に整理します。同じユーザー・同じ日付で登録すると、新しい行を増やさず既存の行を更新します。

- 入力した測定値は、対応する既存値を更新します。
- 空欄の測定値は、既存値を残します。
- 食事ログと行動ログは、既存文にない行を追加します。
- 空の食事ログ・行動ログは、既存文を残します。
- 空ではないメモは既存メモを更新し、空欄なら既存メモを残します。

同じ内容を誤って二重送信しても、`request_id` により同一リクエストを重複登録しにくい設計です。

### 5.5 修正

1. 「修正・削除」タブを開きます。
2. 編集するユーザーを選びます。
3. 登録済みの日付を選びます。
4. 表示された値を変更します。
5. 「更新」を押します。

ユーザーや日付を別の値へ変更する機能ではなく、その記録の測定値・メモ・食事ログ・行動ログを編集する機能です。

編集中に別の画面や処理から測定値が更新された場合は、競合の警告を表示します。入力中の値は勝手に消さず、「競合項目を最新値に置換」を選べます。

### 5.6 削除

1. 一覧で削除したい記録の `id` を確認します。
2. 「修正・削除」タブでIDを入力します。
3. 表示された削除対象を確認します。
4. 確認チェックを入れます。
5. 「削除実行」を押します。

存在しないIDでは削除ボタンが表示されません。削除は取り消せないため、重要なデータは事前にバックアップしてください。

### 5.7 ヘルスチェック

ヘルスチェックでは主に次を確認します。

- 書き込みを担当するWorkerが動作しているか
- SQLiteデータベースを読み取れるか
- 書き込み待ちキューが満杯でないか

状態は `ok`、`degraded`、`unhealthy` のいずれかになります。

## 6. データの保存ルール

### 6.1 1日1件

データベースでは、`ユーザー + 対象日` の組み合わせを重複させません。

例:

- 自分 / 2026-08-14 → 1件
- 父 / 2026-08-14 → 別の1件
- 自分 / 2026-08-15 → 別の1件

### 6.2 主な保存項目

内部では、画面入力に加えて次の管理情報も保存します。

- `id`: 記録を区別する番号
- `request_id`: 同じ送信の重複を防ぐ識別子
- `date`: 対象日（`YYYY-MM-DD`）
- `user_id`: `self` / `father` / `mother`
- `created_at`: 記録を作成した日時

`created_at` は作成日時であり、編集日時を記録する `updated_at` は現在ありません。

### 6.3 保存場所

標準では、リポジトリ直下の `data/biolog.db` に保存します。Docker Composeでは、このファイルをコンテナ外のフォルダーへ残すため、通常はコンテナを停止しても記録は消えません。

## 7. 初心者向けの仕組み説明

BioLogは、次の3つの役割に分かれています。

1. **Streamlit** — ブラウザに画面を表示し、入力を受け取る
2. **FastAPI + Worker** — 入力を確認し、順番に保存する
3. **SQLite** — 健康記録を1つのデータベースファイルに保存する

書き込みの流れは次のとおりです。

```text
ブラウザ画面
  → FastAPI
  → 書き込み待ちキュー
  → 1本のWorker
  → SQLiteデータベース
```

書き込み担当を1本にまとめることで、複数の保存処理が同時にデータベースへ入り「database is locked」になる危険を減らしています。

読み取りはFastAPIを通じて行い、StreamlitからSQLiteを直接開きません。

## 8. API仕様（開発者向け概要）

通常利用ではAPIを直接操作する必要はありません。

| メソッド | パス | 用途 |
|---|---|---|
| `GET` | `/api/health/health` | 動作確認 |
| `POST` | `/api/health/record` | 新規登録・同日更新 |
| `PUT` | `/api/health/record/{record_id}` | ID指定の修正 |
| `GET` | `/api/health/record/day` | ユーザーと日付で1件取得 |
| `GET` | `/api/health/record/{record_id}` | IDで1件取得 |
| `DELETE` | `/api/health/record/{record_id}` | ID指定の削除 |
| `GET` | `/api/health/records` | 一覧取得（ページング対応） |
| `GET` | `/api/health/records/range` | 期間指定の一覧取得 |
| `GET` | `/api/health/records/latest/{user_id}` | ユーザーの最新1件取得 |

APIは不正な日付、逆転した期間、範囲外の数値、未知の項目、長すぎる文章などを拒否します。

## 9. 動作環境と起動

### 必要なもの

- Docker Desktop、またはDocker Engine + Compose v2
- Chrome、Edge、Firefox、Safariなどのモダンブラウザ
- 目安として空きディスク約1GB、メモリ約2GB

Windows 11 + Docker Desktopで動作確認されています。LinuxとmacOSは理論上動作可能ですが、正式な動作確認範囲ではありません。

### 標準の接続先

- 画面: `http://localhost:8501`
- API: `http://localhost:8766`

標準Composeは両方を `127.0.0.1` にだけ公開します。

### Windowsでの簡単な操作

リポジトリ直下に次のバッチファイルがあります。

- `BioLog起動.bat` — 通常起動し、準備後にブラウザを開く
- `BioLog再ビルド起動.bat` — コード変更後などに再ビルドして起動する
- `BioLog停止.bat` — Docker Composeを停止する

Docker Desktopを先に起動してから使用します。

## 10. セキュリティとプライバシー

### 標準構成で行うこと

- UIとAPIをlocalhostだけに公開します。
- 健康記録をローカルのSQLiteへ保存します。
- 入力した健康記録を開発者や第三者へ自動送信しません。
- Streamlitの利用統計送信を無効化しています。
- APIの接続先をlocalhostまたはDocker内部の許可されたホストに制限します。

### 実装していないこと

- ログイン認証
- APIキー、Basic認証、OAuth
- HTTPS / TLS
- レート制限
- 不特定多数向けのアクセス権管理

このため、標準のlocalhost限定を解除しただけの状態で、LANやインターネットへ公開してはいけません。

## 11. バックアップ

記録の実体は `biolog.db` という1つのファイルです。重要な記録は定期的にバックアップしてください。

安全な基本手順:

1. `docker compose down` で停止します。
2. `data/biolog.db` を別の安全な場所へコピーします。
3. `docker compose up -d` で再起動します。

CSVは閲覧・持ち出し用として便利ですが、アプリ全体を元どおりに戻すバックアップはSQLiteファイルを使用します。

## 12. 制約と既知の注意点

- 同時に大人数が使う設計ではありません。
- 認証がないため、公開サービスには向きません。
- 書き込みから画面反映まで数秒かかる場合があります。
- 一覧は1ページ20件です。
- 編集画面で選べる登録済みデータは、現在の実装ではユーザーごとに最大500件を取得します。
- 数万件以上の大量データでの性能は未検証です。
- 数か月単位の長時間連続稼働は未検証です。
- `updated_at` や監査履歴はありません。
- SQLiteを直接編集した場合、アプリの入力チェックを通らないため不正な値が入る可能性があります。
- 強制終了時にmigration lockが残る既知の問題があります。
- Docker Composeの `unhealthy` 表示だけでは、コンテナは自動再起動されません。

## 13. 基本的な利用シナリオ

### 毎日の記録

1. BioLogを開きます。
2. 「新規登録」で人と日付を選びます。
3. 測定できた項目と、その日のメモを入力します。
4. 「登録」を押します。
5. 「グラフ」または「一覧」で反映を確認します。

### 1か月の振り返り

1. サイドバーで開始日と終了日を指定します。
2. 見たいユーザーを選びます。
3. 「グラフ」で推移を確認します。
4. 必要なら「一覧」からCSVを保存します。

### 入力ミスを直す

1. 「修正・削除」を開きます。
2. ユーザーと日付を選びます。
3. 値を修正して「更新」を押します。

## 14. 完了条件（受け入れ確認）

BioLogの基本機能が正常に使える状態とは、次を満たす状態です。

- `http://localhost:8501` で画面を開ける
- ヘルスチェックが `ok` になる
- 自分・父・母を選択できる
- 測定値または文章を1つ以上入力して登録できる
- 登録した値を最新データ・一覧・グラフで確認できる
- 登録済みデータを修正できる
- 削除対象を確認して削除できる
- 選択ユーザー・期間の全件をCSVで保存できる
- Docker停止後も `biolog.db` が残る
